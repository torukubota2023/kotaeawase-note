## C1. ビルドの規律（build.py）

1. `build.py` を2回連続で実行 → 1回目は「注入しました」または「変更なし」、**2回目は必ず「変更なし」**、
   直後の `git diff` が空（冪等）
2. `build.py --check` → exit 0。次に `data/content.yaml` の任意の label を1文字変えて
   `--check` → **exit 1 で「食い違い」検出**（検証後に `git checkout data/content.yaml` で戻す）
3. ネガティブテスト: index.html 末尾に `/* ==== CONTENT:BEGIN ==== */` を書き足した一時コピーで
   実行 → 「マーカーが2個」で exit 1
4. 検証機能: yaml の diseases を6件に減らした一時コピーで exit 1（7件チェック）。
   決定木の `result` を1つ未知IDに変えた一時コピーで exit 1（参照整合・8分類全到達チェック）
5. `sw.js` の VERSION を仮に `v9.9.9` へ変えて build → index.html の APP_VERSION と
   設定画面のバージョン表示が `v9.9.9` になる（確認後に戻して build し直す）

## C3. 画面と導線（モバイルファースト）

1. 5画面が hash で遷移する: `#list`（既定）/`#new`/`#case/<id>`/`#stats`/`#settings`。
   ブラウザの「戻る」で前の画面に戻れる
2. 下部固定ナビは4つ（一覧・＋新規・集計・設定）。**ウィザード（#new）中は消える**
3. 幅 375px で全画面を縦に流し、**横スクロールが発生しない**（DevTools で
   `document.documentElement.scrollWidth <= 375` を各画面で確認）
4. 診察中動線のタップ標的（pointer:coarse 時）: チップ・3値トグル・ウィザード操作バーの
   戻る/一覧へ/次へ・ロックボタンが**実測 48px 以上**（DevTools のモバイルエミュレーションで
   getBoundingClientRect と computedStyle の min-height を確認する。CSS のメディア規則は
   基底定義より**後ろ**にあること ── メディア規則は特異度を上げないので、前にあると
   同特異度の後勝ちで打ち消される。2026-08-08 差分検収で実測発覚・修正済み）。
   **詳細画面などの副次ボタン（.btn.small: 訂正する・一覧へ戻る等、診察外の操作）は
   36px のままで合格**（基準と実装を一致させる精密化）
5. ウィザードの操作バー（戻る/一覧へ/次へ）が**下部固定**で、スクロール位置によらず親指で届く。
   下部アプリナビとは同時に表示されない。コンテンツ最下部がバーに隠れない

## C4. ウィザード S1〜S7 と保存

1. S1: 問いと病態が必須（空のまま「次へ」でブロック）。年代・性別は任意。
   病態は content.yaml の7件（6疾患＋その他）
2. S2: 確信度スライダーと数値入力が連動。予測部位は位置ピッカー（検収手順は C12）
3. S3: 病態別チェックリストが 視診/触診/打診/聴診 のグループ見出しで出て、**priority:true（★）が
   各グループの先頭**。各項目 あり/なし/未評価 の3値、既定は未評価。
   「なし」にした項目が「あるはずなのに無かった所見」へ**自動で並ぶ**（手動追加・削除も可）
4. 入力途中でタブを閉じ、開き直す → #list 上部に再開バナー、押すと**同じステップに入力が残って**復帰
   （保存は input から 300ms debounce）
5. localStorage を DevTools で見る: `awn.case.<id>` が1症例1キー、`awn.meta`（schemaVersion:1）、
   checks は 1/-1/キー欠落 の3状態
6. 「その他」病態: チェックリスト部が出ず、自由記載だけで S7 まで同じ流れが回る
7. 片手高速入力（S1）: 病態 → 側 → 問いテンプレ の**3タップで問いが入る**。テンプレ文言は
   content.yaml の quick_templates.questions（◯を側で置換）。転記後も自由編集でき、手書きの
   問いをテンプレで置き換えるときだけ確認が出る。側チップは予測部位（pre.site.sides）にも入る。
   「その他」ではテンプレブロック非表示。匿名注意の下に ui_copy.quick_hint の一行
8. 片手高速入力（S2）: 確信度プリセット 30/40/50/60/70/80/90 がタップ即設定（スライダー・
   数値入力と連動して残る）。第一候補のサジェストチップ（first_dx_patterns の組み立て。
   例: 病態「胸水」＋側「右」→「右 胸水」「胸水」）はタップで入力・以後編集可
9. 下部ナビ「＋新規」と一覧の「＋新しい記録」は**常に新しい記録を開始する**。詳細画面の
   「訂正する/編集する」でウィザードに入った直後に押しても、その症例の編集を引きずらない
   （訂正中の入力は逐次保存済みなので失われない。2026-08-08 差分検収で修正）。
   下書きの再開は #list の再開バナー・一覧の行タップ・直接 #new を開いたときの
   チューザーで従来どおり

## C5. ロック規律（本アプリの核心）

1. S4 のボタン文言は content.yaml の `lock_button`、確認ダイアログは `lock_confirm`
2. ロック後、DevTools で `awn.case.<id>` を見る: `lock.lockedAt` と `lock.snapshot`
   （S1〜S3 の deep copy）が保存されている
3. ロック後に S1〜S3 へ戻ると**読み取り専用**。「訂正する」→確認→編集可になり、
   `editedAfterLock:true`（不可逆）と `editLog` が付く
4. 訂正後、「画像後修正あり」バッジが **一覧・詳細・書き出しテキスト**に出て、消す手段がない。
   集計は症例別の表示を持たないため、#stats では対象件数の直下の
   **「うち画像後修正あり n 件」の注記**で示す（実装に合わせ検収 2026-08-08 更新）。
   **ロック解除機能が存在しない**
5. 訂正で確信度を変えても、S6 対比・書き出し・集計の「画像前」は**ロック時点の snapshot の値**のまま
6. コンソールで直接 `writeCase(＜locked case＞, "exam", ...)` を呼ぶと拒否される（データ層ガード）

## C6. S5〜S7（POCUS・対比・書き出し）

   `70% → 80%（↑10）` 形式の動きが自動表示（↓n・±0 も）
2. S6: 左＝ロック時点 / 右＝POCUS 後 の2カラム対比。外れ方は8カード直接選択と
   決定木モーダルの両方から選べる。**主分類（8分類 or 外れなし）の明示選択なしでは S7 へ進めない**。
   副分類は任意。observation/technique/interpretation/integration を選ぶと next_hints のヒントが出る。
   予測どおりだった症例は、8カードと見た目の違う「外れなし（予測どおり）」
   （ui_copy.no_miss_label・破線枠。データは missPrimary="none"）を選んで進む——選ぶと
   決定木ボタン・副分類・ヒントが消えるが、**次の一手・teaching point は書ける**。
   書き出しの分類行は「外れなし（予測どおり）」、#stats の8分類内訳では別枠1行（2026-08-08 追加）
3. 決定木で**8分類すべてに到達できる**（経路は8本: q0→q0b→conditions/timecourse/reference、
   q0→qa→anatomy、qa→q1→q2take→technique/observation、q1→q2read→interpretation/integration）
4. S7: 書き出しプレビューが content.yaml の export_template **見出し順そのまま**。
   ヘッダに記録ID・ロック時刻・画像後修正の有無、冒頭に匿名確認の一行。
   コピー失敗環境（iOS で clipboard 拒否）では readonly textarea 全選択のフォールバック
5. 巻末テンプレ（ガイド tables[66]）と見出し構成が同一であることを、記入例（架空・肺炎）を
   通しで入力して突き合わせる

## C7. 詳細画面・後日追記・一行記録

1. `#case/<id>`: 全項目の読み取り表示＋「後日追記」（CT・検査・最終診断・時間差・
   一致判定 はい/部分/いいえ/未確定）＋「訂正する」＋書き出し
2. 一致判定を「はい/部分/いいえ」にすると集計対象になる
3. #list の「一行記録」→ 日付（既定今日）＋ zure/next の2フィールド → 一覧に時系列で小さく混在表示
4. 補記（画像後・append-only）: 詳細画面の「補記を足す」で何度でも追記できるが、
   **編集・削除のUIが存在しない**。追記しても「画像後修正あり」バッジは付かず、snapshot・
   採点・集計も変わらない。書き出しテキストの**末尾**に「■ 補記（画像後）」ブロックが
   各行時刻つきで出る（ヘッダの「画像後修正: あり/なし」とは独立）。近くに ui_copy.addendum_note

## C8. 集計（手計算照合）

ダミー6件を入力する（すべてロック→S7完了→後日追記まで）。確信度はロック時の値:

| # | 病態 | ロック時確信度 | POCUS後 | 一致判定 | 主分類 |
|---|---|---|---|---|---|
| 1 | 肺炎 | 90 | 95 | はい | 観察の誤り |
| 2 | 肺炎 | 80 | 60 | 部分 | 手技の誤り |
| 3 | 肺炎 | 70 | 90 | はい | 解釈の誤り |
| 4 | 肺炎 | 50 | 20 | いいえ | 統合の誤り |
| 5 | 肺炎 | 30 | 40 | 部分 | 解剖の理解不足 |
| 6 | 胸水 | 20 | 10 | いいえ | 診察条件の制約 |

1. **4件目まで**入力した時点で #stats は数字を出さず `small_n_note`（5例未満…）を表示
2. 6件そろったら（的中スコア はい=100/部分=50/いいえ=0、外れ幅=確信度−スコア）:
   平均外れ幅 **+6.7**、平均絶対外れ幅 **26.7**、
   POCUS 前後の確信度移動（絶対値平均）**15.8**・**↑3件・↓3件**。
   移動の定義: POCUS 後の確信度 − ロック時（snapshot）の確信度。**絶対値の平均**で出し
   （符号付き平均は±が打ち消し合うので使わない）、pocus 後の確信度を入力した記録のみが対象、
   ±0 は↑↓の件数に数えない（上の6件では +5/−20/+20/−30/+10/−10 → 95÷6＝15.8）
3. 較正表: 0–20%（n=1 確信度20/的中0）、21–40%（n=1 30/50）、41–60%（n=1 50/0）、
   61–80%（n=2 75/75）、81–100%（n=1 90/100）
4. 8分類内訳: 観察/手技/解釈/統合/解剖/条件 が各1、時間変化/比較基準 が0。
   別枠の「外れなし（予測どおり）」行は 0 件（外れなしの症例を1件足すと、この行だけが増え
   8本の棒は変わらない）
5. 疾患フィルタで「胸水」→ n=1 になり small_n_note に切り替わる

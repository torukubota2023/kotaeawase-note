前提: リポジトリ `~/知的解説/4_アプリ/kotaeawase-note/`、Python は
`/Users/torukubota/ai-management/.venv/bin/python`（PyYAML・Pillow 入り）。

## C1. ビルドの規律（build.py）

1. `build.py` を2回連続で実行 → 1回目は「注入しました」または「変更なし」、**2回目は必ず「変更なし」**、
   直後の `git diff` が空（冪等）
2. `build.py --check` → exit 0。次に `data/content.yaml` の任意の label を1文字変えて
   `--check` → **exit 1 で「食い違い」検出**（検証後に `git checkout data/content.yaml` で戻す）
3. ネガティブテスト: index.html 末尾に `/* ==== CONTENT:BEGIN ==== */` を書き足した一時コピーで
   実行 → 「マーカーが2個」で exit 1
4. 検証機能: yaml の diseases を6件に減らした一時コピーで exit 1（7件チェック）。
   決定木の `result` を1つ未知IDに変えた一時コピーで exit 1（参照整合・8分類全到達チェック）
5. `sw.js` の VERSION を仮に `v9.9.9` へ変えて build → index.html の APP_VERSION と
   設定画面のバージョン表示が `v9.9.9` になる（確認後に戻して build し直す）

## C2. 医学文言の突合（content.yaml ⇔ ガイド DOCX）

1. `data/content.yaml` の転記元は `docs/content_map_reconciliation.md` に段落・表番号つきで記録
   されている。**最低10項目を無作為に選び**、ガイド DOCX
   （`~/ai-management/docs/education/呼吸器身体診察実践ガイド_2026_統合版.docx` tables[17]〜[22]・
   tables[56]・tables[66]・段落1211〜1238）の実物と逐語で突き合わせる
2. アプリ画面に出る医学文言（チェックリスト項目・8分類の名前と説明・決定木の問い・
   書き出し見出し・ロック文言）が content.yaml と一致する（index.html 側での言い換えが無い）
3. **文献の公表尤度比・感度・特異度が、数値としてどこにも無い**（2026-08-09 裁定で線引きを改訂:
   「尤度比」「感度」「特異度」「LR」の**語**は v1.2.0 の「自分の尤度比（実測）」ブロックの
   枠組み（ui_copy）として現れてよいが、**数値はすべて実行時に使用者の記録から算出**され、
   ソースに定数として存在しない）。機械検査（どちらも 0 件）:
   - `grep -vF "const CONTENT" index.html | grep -cE "(\blp|\bln|\bsens|\bspec)\s*[:=]\s*[0-9]"`
   - `grep -vF "const CONTENT" index.html | grep -cE "(LR\+|LR−|尤度比|感度|特異度)[^、。]*[0-9]+\.[0-9]"`

## C3. 画面と導線（モバイルファースト）

1. 5画面が hash で遷移する: `#list`（既定）/`#new`/`#case/<id>`/`#stats`/`#settings`。
   ブラウザの「戻る」で前の画面に戻れる
2. 下部固定ナビは4つ（一覧・＋新規・集計・設定）。**ウィザード（#new）中は消える**
3. 幅 375px で全画面を縦に流し、**横スクロールが発生しない**（DevTools で
   `document.documentElement.scrollWidth <= 375` を各画面で確認）
4. 診察中動線のタップ標的（pointer:coarse 時）: チップ・3値トグル・ウィザード操作バーの
   戻る/一覧へ/次へ・ロックボタンが**実測 48px 以上**（DevTools のモバイルエミュレーションで
   getBoundingClientRect と computedStyle の min-height を確認する。CSS のメディア規則は
   基底定義より**後ろ**にあること ── メディア規則は特異度を上げないので、前にあると
   同特異度の後勝ちで打ち消される。2026-08-08 差分検収で実測発覚・修正済み）。
   **詳細画面などの副次ボタン（.btn.small: 訂正する・一覧へ戻る等、診察外の操作）は
   36px のままで合格**（基準と実装を一致させる精密化）。
   ただし決定木モーダルの「ひとつ戻る」「閉じる」（.treenav）は 48px 以上、復元の file input と
   select（集計フィルタ・S1 年代/性別）は 44px 以上であること（2026-08-22 K-Q4）
5. ウィザードの操作バー（戻る/一覧へ/次へ）が**下部固定**で、スクロール位置によらず親指で届く。
   下部アプリナビとは同時に表示されない。コンテンツ最下部がバーに隠れない
6. モーダル（補記・一行記録・決定木）は**ソフトキーボードが出ても入力欄が隠れない**
   （2026-08-22 K-S2）。`window.visualViewport` の height/offsetTop に overlay の top/bottom を
   合わせ込み、シートの max-height も見えている高さ内に収める。鍵盤が引っ込めば元に戻る。
   `visualViewport` の無い環境（デスクトップの古い版等）では何もせず従来どおり 88vh で表示され、
   例外も出ない。モーダルを閉じたら resize/scroll のリスナーを外す（実機 iPhone で要確認）

   チューザーで従来どおり

## C5. ロック規律（本アプリの核心）

1. S4 のボタン文言は content.yaml の `lock_button`、確認ダイアログは `lock_confirm`
2. ロック後、DevTools で `awn.case.<id>` を見る: `lock.lockedAt` と `lock.snapshot`
   （S1〜S3 の deep copy）が保存されている
3. ロック後に S1〜S3 へ戻ると**読み取り専用**。「訂正する」→確認→編集可になり、
   `editedAfterLock:true`（不可逆）と `editLog` が付く
4. 訂正後、「画像後修正あり」バッジが **一覧・詳細・書き出しテキスト**に出て、消す手段がない。
   集計は症例別の表示を持たないため、#stats では対象件数の直下の
   **「うち画像後修正あり n 件」の注記**で示す（実装に合わせ検収 2026-08-08 更新）。
   **ロック解除機能が存在しない**
5. 訂正で確信度を変えても、S6 対比・書き出し・集計の「画像前」は**ロック時点の snapshot の値**のまま
6. コンソールで直接 `writeCase(＜locked case＞, "exam", ...)` を呼ぶと拒否される（データ層ガード）

ダミー6件を入力する（すべてロック→S7完了→後日追記まで）。確信度はロック時の値:

| 3 | 肺炎 | 70 | 90 | はい | 解釈の誤り |

   POCUS 前後の確信度移動（絶対値平均）**15.8**・**↑3件・↓3件**。

## C9. バックアップ・復元・消去

1. 設定 →「JSON をダウンロード」→ `kotaeawase-backup-YYYYMMDD.json` が落ち、
   中身に cases（全件）と quick が入っている
2. 全消去（二重確認）→ 一覧が空 → 復元でさっきの JSON → 件数表示 → 全置換 →
   **消去前と同じ一覧・同じ詳細**（記録ID・snapshot・バッジまで一致）
3. マージ: 片方の端末側で1件だけ更新した JSON を読み込み → 同IDは updatedAt の新しい方が残る
4. 未バックアップ5件以上で #list にバナー
5. 設定に使用量概算・persist 要求ボタン・bedside-bayes リンク（尤度比はこちら）・
   guide_ref / nejm_ref のクレジット・APP_VERSION がある
6. 共有シート経由の保存（2026-08-22 K-S3）: `navigator.canShare({files:[…]})` が真なら
   共有シート（→「ファイルに保存」）へ JSON ファイル1件を渡す。ホーム画面追加の
   スタンドアロン起動で保存 UI が出ない iOS の穴を塞ぐための経路
7. **共有をキャンセルしたら `lastBackupAt` を更新しない**（K-S3 の要）。
   保存していないのに「バックアップ済み」と表示する事故を防ぐ。確認は3経路すべて:
   ①キャンセル（AbortError）→ 日時は前回のまま・「共有をやめました。バックアップは
   保存されていません」／②共有成功 → 日時更新／③`canShare` が偽、または共有が
   AbortError 以外で失敗（NotAllowedError 等）→ 従来の a.click() ダウンロードへ落ちて日時更新

### C13.4 書き出し（personal-panel 契約 version 1）

1. 「自分パネルを書き出す（ベイズ診察エンジンへ）」は**閾値を満たした行がある病態にだけ**出る。
   橋が架かるのは 肺炎→cap・胸水→eff・心不全→hf・COPD→copd の4病態
   （bedside-bayes v2.8.1 の DB キーを実物確認 2026-08-09）。気胸・喘息・その他は
   plr_no_bridge_note を表示しボタンなし
2. 書き出し JSON（クリップボード。コピー不可環境では全選択フォールバック）:
   `{"app":"kotaeawase-note","type":"personal-panel","version":1,"exportedAt":"<ISO8601>",`
   `"disease":{"noteId":"effusion","bedsideKey":"eff","label":"胸水"},"n":{"present":12,"absent":10},`
   `"findings":[{"id":"ef_stony_dullness","nm":"石様濁音（stony dull）（実測）","cat":"打診",`
   `"lp":3.75,"ln":0.3125,"ci":[1.0406268491224149,13.513489500928449],`
   `"cin":[0.11180673472724434,0.8734379931426774],`
   `"counts":{"tp":9,"fp":2,"fn":3,"tn":8},"sens":0.75,"spec":0.8,"corrected":false}]}`
   - **sens/spec/lp/ln/ci/cin は丸めない全精度**（2026-08-09 bedside v2.9.0 取り込み仕様。
     エンジン側が「JSON 内の sens/spec から再計算した lp と JSON 内の lp が ±1% で整合」を
     検証するため、丸めると特異度99%台の行で拒否される。表示用の丸めはノートのUI側だけ）
   - lp=sens/(1−spec)、ln=(1−sens)/spec を **JSON に書いた sens/spec と同じ値**から計算
     （補正時は補正後の一組で一貫させ corrected:true）
   - 検算例: counts 9/2/3/**13** なら sens 0.75・spec 13/15 → lp は **5.625**
     （契約説明の旧例示 5.2 は counts と不整合な悪い例）
3. findings に閾値未満の行（呼吸音著明な減弱）が**入っていない**。
   **LR+ の大小では絞らない** ── 閾値（各10例）さえ満たせば LR+≤1 の「不成立実測」も書き出す
   （エンジン側が「実測では判別できず」と表示する仕様）
4. ボタン近くに「書き出しはクリップボードへのコピーです。どこに貼るかは、あなたが決めます。」

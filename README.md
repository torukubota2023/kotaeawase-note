# 答え合わせノート ── 画像を開く前に書く

画像検査（POCUS・胸部X線・胸部CT）による身体診察の較正支援アプリ。画像を開く**前**に予測と確信度（%）を書いてロックし、
画像で答え合わせをして、外れ方を8分類し、次の一手をひとつ決める。単一 HTML・依存ゼロ・通信ゼロの PWA。

- **公開URL:** https://torukubota2023.github.io/kotaeawase-note/ （GitHub Pages）
- 位置づけ: [bedside-bayes](https://torukubota2023.github.io/bedside-bayes/) ＝ 尤度比・情報量の**数値の正本**、
  本アプリ ＝ ガイド第10章 06.5「症例で較正する」の**手順の実装**
- **数値の線引き（2026-08-09 裁定で改訂）:** 文献の公表尤度比・感度・特異度は従来どおり**載せない**
  （数値の正本は bedside-bayes）。v1.2.0 からは、**使用者自身の記録だけから端末内で算出した実測値**
  （「自分の尤度比」）を表示する。ソースコードに診断数値の定数は存在しない
  （検収 C2.3 の機械検査で担保）

## 自分の尤度比（v1.2.0）

- **軸1（定性）:** ロック時点の所見（あり/なし）× 後日追記「S1の病態は、実際にあったか」の 2×2 から、
  (病態, 所見) ごとの感度・特異度・LR± を 95%CI つきで算出。**病態あり10例・なし10例が揃うまで
  数値を出さない**（進捗のみ表示）。verification bias の注記を固定表示
- **軸2（定量):** 定量の問い（qtype=quant）の予測値−実測値から、病態×単位ごとに
  平均ずれ・SD・RCV（√2×1.96×SD）を表示（n≥5）
- **書き出し:** 閾値を満たした行だけを personal-panel 契約（version 1）の JSON で
  クリップボードへ。bedside-bayes へ橋が架かるのは 肺炎(cap)・胸水(eff)・心不全(hf)・COPD(copd) の4病態のみ
- 軸3（予後）は未実装 ── 構想は `docs/personal_lr_design.md`

## データの扱い（最重要）

- 記録は**この端末の localStorage のみ**。サーバー送信ゼロ・外部リソース読み込みゼロ・解析ツールなし
- 患者の氏名・ID・病室番号は**入力欄を作っていない**。年代（10歳刻み）・性別のみ任意。
  自由記載欄には匿名注意の placeholder、書き出しテキストの冒頭に匿名確認の一行が入る
- **端末の中にしかない ＝ 消えることがある**。設定画面から
  1. 「端末にデータ保持を要求する」（`navigator.storage.persist()`）を一度押す
  2. 定期的に「JSON をダウンロード」でバックアップ（`kotaeawase-backup-YYYYMMDD.json`）
  3. 未バックアップが5件たまると一覧にバナーが出る
- 復元は設定画面から JSON を選び、件数を確認のうえ「全置換」か「マージ」（同じ記録IDは更新の新しい方）
- **症例の個別削除は意図的に無い**。外れた記録だけ消せると較正記録の選別になるため、
  ロック解除を作らないのと同じ思想で作っていない。試し入力の整理は「全消去」→バックアップ
  からの「復元」で行う。画像後に気づいたことは「補記」（append-only・採点に使わない）へ

## 開発・運用

### 医学コンテンツは content.yaml だけを編集する

医学文言（チェックリスト・外れ方8分類・決定木・書き出し見出し・ロック文言）の正本は
`data/content.yaml`。index.html の CONTENT 区間は build.py の生成物なので**手で編集しない**。

```bash
# 注入（PyYAML は ai-management の venv にある）
/Users/torukubota/ai-management/.venv/bin/python build.py

# コミット前必須：yaml だけ直して注入を忘れていないかの検査（差分があれば exit 1）
/Users/torukubota/ai-management/.venv/bin/python build.py --check
```

build.py は注入と同時に検証する: diseases 7件 / 項目 id の全体一意 / 外れ方分類 8件 /
決定木の参照整合と8分類全到達 / export_template 8項目（subfields 本数はアプリが位置参照するため固定）。
2回連続で実行しても差分ゼロ（冪等）。

### 更新したら sw.js の VERSION を必ず上げる

`sw.js` はネットワーク優先＋キャッシュ予備。**VERSION を上げ忘れると、既訪端末がオフラインに
落ちたとき旧版キャッシュのまま残り続ける**（bedside-bayes 開発中に実際に踏んだ穴）。
VERSION は build.py が index.html の `APP_VERSION`（設定画面とフッターの表示）へ転記するので、
上げたら build.py を再実行してからコミットする。

### アイコン

`icons/icon.svg` が原本。PNG（192/512/apple-touch-icon）は生成物:

```bash
/Users/torukubota/ai-management/.venv/bin/python make_icons.py
```

## ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（配布物）。CONTENT/APPVER 区間のみ build.py が管理 |
| `data/content.yaml` | 医学コンテンツの正本（転記元との突合は `docs/content_map_reconciliation.md`） |
| `build.py` | yaml → CONTENT 注入。検証・冪等・`--check`・VERSION 転記 |
| `sw.js` | オフライン用 Service Worker（ネットワーク優先・VERSION 手動 bump） |
| `manifest.webmanifest` / `icons/` | PWA メタデータとアイコン |
| `docs/acceptance.md` | 検収チェックリスト（経緯を知らない検証者向け） |

## 更新履歴

### v1.17.1（2026-08-31）

**経過モードで、選んだチップが光っていなかった。** v1.9.0 以来、段階・区域・参照・登録時の
部位/性状/軸のすべてが `.on` クラスで選択を持つのに `.chip.on` の規則が無く、
押しても見た目が変わらなかった（データは正しく保存されていた）。毎日タップするだけの画面で
何を選んだか読めない状態だったため、`.chip[aria-pressed="true"]` と同じ配色を当てた。
ライト・ダークとも実測（ダークのコントラスト 8.54）。

### v1.17.0（2026-08-31）

**経過モードを「変化を読む条件」ごと実装した。** 監査で、微分の計算（参照との符号一致・目盛り・
盲検ガード）は実装済みだが、シリーズが教える成立条件の二つ ── ①同じ人が取っていること
②再現性の床を知っていること ── がどちらも欠けていることが分かったため。

- **「今日は自分が取っていない」チップ**。その日をまたぐ区間は集計で数えず、翌日からの
  新しい基準にする（ガイド「検者が替わった日は Δ を読まない」の実装）。履歴に「他」印
- **二度取り**。今日の行を保存した後だけ、値を伏せて取り直し、一致数だけを記録する
  （2回目の値は保存しない）。所見ごとの累計を集計行に併記。閾値判定はしない
- **当日の入力を1タップごとに保存**。回診で中断しても消えない（obs には入れないので
  「全所見そろって1日ぶん」の規律は不変）
- 目盛りが空欄のときに既定文を黙って保存するのをやめ、「未固定」と名乗ってあとから書けるように
- 「・動かず N 回」の表示／性状の並びが全区間逆向きのときの警告／7日超の間隔の注記

### v1.16.0（2026-08-30）

**人間工学の実測（iPhone 実寸 375px）にもとづく UI 改良と、フィードバックの環を閉じる3点。**
表示名は副院長裁定: 利用者向け文言に統計用語（ブライアスコア・二乗・較正 等）を使わない。
タイルは「確信度のずれ（小さいほど良い）」、説明は平易な1文＋畳んだ「この数字の読み方」。

- **ダークモード対応（OS 設定に自動追従）**: 直書き色42箇所を役割つき変数に集約し、
  暗色パレットを追加。当直の暗所で白画面を出さない。全ペアのコントラストを実測し
  WCAG AA 合格（最低 6.17）
- **文字を大きめに（設定・既定オフ）**: 本文14→16px ほか読み文字だけ1段上げる
- **集計の説明の壁を解消**: 11px×485字の連続を「常時1文＋畳み」に再構成。
  常時表示は「0が最良。小さいほど、自信のつけ方が実際の結果に合っています。
  自信満々で外すほど大きくなります。」の1文のみ
- **確信度の頻度言い換え**: 「70% ＝ 10回に3回は外れる想定」を S2・S5 の確信度に連動表示
  （91〜99% は「およそm回に1回」、100% は「外れない、という宣言」）
- **書く前に外の視点**: その病態の判定済みが5件以上あるとき、S2 に
  「この病態でのあなたの実績：n件・確信度のずれ 0.xx」を1行
- **答えが出た瞬間の1件フィードバック**: 一致判定を入れた直後に
  「この1件：確信度70% → 的中。あなたの確信度のずれ 0.18 → 0.16（小さくなった＝良い）」
  （5件未満は件数のみ）
- スライダーのつまみを 28px のカスタム描画に（細くて掴みにくかった）
- 「全部50%と書くと0.25」の言い切りを数式と整合する形に修正（「部分」=0.5 が混ざると
  小さく出るため、はい/いいえで答えが出た記録に限る旨を明記）
- 較正表 → 「確信度と的中の対応表」に改称。描画される全画面で統計用語0件を機械走査で確認

### v1.15.0（2026-08-30）

**採点を「正直さが得をする」形に変えた（副院長の指摘: 絶対値の平均は 100% と言い切る人ほど
良い成績に見える）。あわせて「この画像で決まったか」を1タップで残せるようにした。**

- 集計の主役タイルを「平均絶対外れ幅」→「ブライアスコア（外れの二乗平均）」に交換。
  全部 50% で 0.25、言い切って外すと大きく減点。符号つき平均外れ幅は自信過剰の向きを
  示すので残した（100% 連発は +30 と出て警告される）
- S5 に「この画像で、答えは決まりましたか（任意）」チップ。決まった回は「確信度移動」の
  集計から除外（その移動は画像の寄与ではなく事前の迷いの量を測ってしまうため）。
  詳細・書き出しにも記入時のみ1行出る。旧記録はフラグ無し＝数字は一切変わらない
- 「画像後の確信度」で測ったブライアを参考表示（決まった回は答えそのものなので採点しない）
- 集計の疾患フィルタを snapshot の病態で適用（軸1と同じ規則に統一）

### v1.14.0（2026-08-30）

**臨床使用開始前の全行監査で見つけた落とし穴 9 件＋1 件を塞いだ。**

- SW: 失敗応答・別オリジン応答をキャッシュしない（病院ゲスト Wi-Fi のログインページが

  （iOS では Safari タブとホーム画面アプリで保存場所が別空間になるため）
- ロック・S7 完了は保存成功を確認してから進む（失敗時は元に戻して alert で止める。
  成功トーストが失敗トーストを上書きし、端末に残らないままロック済みと信じさせる穴を塞いだ）

- 復元「全置換」は全書き込みの成功を確かめてから旧記録を消す（マージも失敗件数を報告）

- 未バックアップのままの人にも初回記録から 14 日で督促バナーを出す
- 未バックアップ件数に経過（tracks）を含める
- 追加案内モーダルの危険説明が存在しないキー（ui_copy.home_risk）を指して空段落に

### v1.7.0（2026-08-24）

**答え合わせを POCUS 以外の画像検査（胸部X線・胸部CT・その他）でもできるようにした。**
X線は POCUS より答えの細かさが落ちるが、較正の機会を逃さないための拡張（副院長要望）。

- S5 冒頭に「答え合わせに使った画像（主たる一つ）」の選択チップ（POCUS／胸部X線／胸部CT／その他。既定 POCUS）。
  複数の画像で答え合わせした場合は主たる一つを選び、後から撮った画像は従来どおり「後日追記」に書く
- 胸部X線・CT の所見チェックリストを6病態に追加（定義の出典は Fleischner Society 用語集 2024
  ほか一次資料。`data/content.yaml` の meta.sources 参照。感度・特異度・尤度比は従来どおり載せない）
- X線・CT では位置に**肺葉チップ**（右上葉〜左下葉・舌区）。BLUE 点プリセットとエコー参照図は POCUS のときだけ
- 答え入力後にモダリティを切り替えるときは確認を挟み、切替の事実を記録に残す
  （入力済みデータは消えず、戻せば復活する）
- 集計の「POCUS 前後の確信度移動」は POCUS の記録だけで計算し、他の画像の件数は注記に出す
  （CT はほぼ確定情報で、混ぜると移動幅が構造的に釣り上がるため）
- 旧記録はすべて POCUS として読まれ、表示・書き出し・集計の互換を保つ
  （書き出しの変更は見出し「4. 画像後の更新」と「画像の種類」行の追加のみ）
- ⚠ 旧版アプリ（v1.6 以前）で v1.7 のバックアップを読み込むと、X線/CT の記録も POCUS の見出しで
  表示される（データは壊れない）

**iPhone で片手で使えるようにした（操作系の表示・配置・寸法のみ。医学文言＝`data/content.yaml` とロック規律・採点ロジック・書き出し形式は不変）。**
